# 文档策略

> 适用范围：`docs/` 下全部文档与图表。目标是让「每个阶段该产出什么文档、
> 用什么格式、叫什么名字」清晰可查，避免临到答辩才补材料。
> 版本：v1.0　生效日期：2026-10-05

## 一、文档目录结构（按阶段编号）

```
docs/
├── 00-项目规范/          项目规范（本目录：文件/Git/文档三大策略）
├── 01-开题/              开题报告、选题论证、开题答辩材料
├── 02-需求分析/          需求规格说明书、用例图、调研记录
│   └── 图表源文件/       本阶段图表源文件（.puml / .drawio）
├── 03-系统设计/          概要/详细设计说明书、数据库设计、接口设计
│   └── 图表源文件/       本阶段图表源文件（.puml / .drawio）
├── 04-测试/              测试计划、测试用例、测试记录与报告
└── 05-论文与答辩/        毕业论文各版次、答辩 PPT、演示材料
```

## 二、各阶段文档清单

| 阶段 | 文档 | 格式 | 产出时机 |
| --- | --- | --- | --- |
| 开题 | 开题报告 | Word / PDF | 开题答辩前 |
| 需求分析 | 需求规格说明书（含用例图） | Markdown | 开题后 |
| 系统设计 | 系统设计说明书（架构、模块） | Markdown | 编码前 |
| 系统设计 | 数据库设计说明书（E-R 图、数据字典） | Markdown | 建表前 |
| 系统设计 | 接口设计文档（API 清单） | Markdown | 前后端联调前 |
| 测试 | 测试计划 + 测试用例 + 测试报告 | Markdown / 表格 | 系统联调后 |
| 论文与答辩 | 毕业论文（初稿/终稿） | Word / PDF | 见进度表 |
| 论文与答辩 | 答辩 PPT、演示视频 | PPT / MP4 | 答辩前 |

> 交付类文档（开题报告、论文）用 **Word/PDF** 便于打印提交；
> 过程类文档用 **Markdown** 便于随代码一起版本控制、方便检索与修改。

## 三、命名规范

- 文档文件名用**中文 + 选填两位数字编号**：
  - `需求规格说明书.md`、`数据库设计说明书.md`、`接口设计文档.md`
  - 有多个版本时用后缀区分：`毕业论文-初稿.docx`、`毕业论文-终稿.docx`
- 禁止 `最终版`、`终版2`、`新建` 之类命名；版本用 Git 管理，不靠文件名堆叠。
- 图表文件与文档同名 + 类型后缀：`E-R图.drawio`、`E-R图.png`。

## 四、图表与源文件

- **每张图都要保留可编辑源文件**（draw.io 的 `.drawio`、PlantUML 的 `.puml`），
  放在**各阶段目录**下的 `图表源文件/`（如 `docs/02-需求分析/图表源文件/`）；
  导出的图片与对应文档同目录，便于插入论文。
- 图统一按「图N-名称」命名（如 `图1-系统总体用例图.puml` / `.png`），源文件与导出图同名。
- 论文中引用的图，源文件必须能重新导出，答辩前若需改图可直接修改源文件。
- 图编号与文档/论文章节对应（如「图 4-1 系统功能结构图」）。

## 五、文档与代码、论文的对应关系

三者应保持一致，避免各说各话：

| 文档 | 对应代码 | 对应论文章节 |
| --- | --- | --- |
| 需求规格说明书 | 功能模块划分 | 第 3 章 需求分析 |
| 数据库设计说明书 | `database/*.sql`、`entity/` | 第 4 章 数据库设计 |
| 接口设计文档 | `controller/`、前端 `api/` | 第 5 章 系统实现 |
| 测试报告 | 测试代码与测试数据 | 第 6 章 系统测试 |

**代码改了，对应的设计文档与论文相关章节要同步更新。**

## 六、版本管理

- 所有 Markdown 文档与图表源文件**随代码一起提交**到 Git，
  提交信息用 `docs(scope): 描述`。
- 开题报告、论文各版次也入库（`.docx` 二进制），以便回溯修改过程。
- 阶段性文档定稿后可导出 PDF 一并提交，方便随时查看。

## 七、何时更新本文档

文档体系调整（新增阶段、改变格式约定）时，先更新本文档，
再补建目录，并在提交信息中注明 `docs(规范)`。
