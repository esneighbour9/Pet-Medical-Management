# 文件策略

> 适用范围：本仓库全部文件。目标是一眼能看出「什么文件该放哪里」、
> 「文件和目录叫什么名字」，避免后期因命名混乱导致返工。
> 版本：v1.0　生效日期：2026-10-05

## 一、目录总览

```
.
├── backend/          Spring Boot 后端工程（含 pom.xml、src/，Maven 标准布局）
├── frontend/         Vue 3 前端工程（含 package.json、src/、vite.config.js）
├── database/         SQL 脚本：建表 DDL、初始化数据、字典数据
│   ├── schema.sql          建表语句
│   ├── data.sql            基础数据（角色、科室、管理员账号等）
│   └── upgrade/            增量变更脚本，按 V1__xxx.sql、V2__xxx.sql 编号
├── deploy/           部署配置：Nginx 配置、Dockerfile、启动/停止脚本
├── scripts/          开发辅助脚本：数据导出、批量导入、格式检查等
├── docs/             全部文档（详见「03-文档策略」）
│   ├── 00-项目规范/
│   ├── 01-开题/
│   ├── 02-需求分析/
│   ├── 02-需求分析/
│   │   └── 图表源文件/     本阶段图表源文件（.puml / .drawio）
│   ├── 03-系统设计/
│   │   └── 图表源文件/     本阶段图表源文件（.puml / .drawio）
│   ├── 04-测试/
│   └── 05-论文与答辩/
├── .gitignore
├── .gitattributes
├── CLAUDE.md
└── README.md
```

## 二、各目录职责边界

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `backend/` | Java 源码、资源、Mapper XML、单元测试、pom.xml | 前端代码、SQL 全量脚本 |
| `frontend/` | Vue 页面、组件、路由、状态、静态资源 | 后端接口实现 |
| `database/` | 建表与初始化 SQL、增量脚本 | 业务代码 |
| `deploy/` | 部署与运维配置 | 开发期临时文件 |
| `docs/` | 各类文档与图表源文件 | 代码、数据库脚本 |
| `scripts/` | 一次性或可复用的工具脚本 | 业务逻辑代码 |

判断准则：**一个文件只属于一个模块目录**；跨模块的公共约定写进 `docs/00-项目规范/`。

## 三、命名规范

### 3.1 目录与文件名

- 代码相关目录与文件：**全小写英文**，多个单词用连字符或下划线，不用中文、不用空格。
  例：`pet-record`、`appointment.vue`、`user-service.java` 不允许中间大写。
- 文档文件名：**中文**，重要文档可加两位数字编号前缀。
  例：`01-文件策略.md`、`需求规格说明书.md`、`E-R图.png`。
- 禁止出现「新建文档」「未命名」「副本」「最终版」「最终版2」这类名称。

### 3.2 Java 规范

- 基础包名：**`com.petmedical`**（如后续确定学校/个人域名，统一改这一处即可）。
- 分包结构（按分层，不按功能切分时）：

```
com.petmedical
├── PetMedicalApplication.java   启动类
├── common/       通用返回结构、常量、枚举、异常
├── config/       配置类（MyBatis-Plus、CORS、拦截器注册等）
├── security/     JWT 工具、鉴权拦截器、当前用户上下文
├── controller/   接口层
├── service/      业务层（接口 + impl 子包）
├── mapper/       数据访问层接口
├── entity/       数据库实体
├── dto/          入参对象
├── vo/           出参对象
└── util/         工具类
```

- 类名 `PascalCase`，方法/变量 `camelCase`，常量 `UPPER_SNAKE_CASE`。

### 3.3 数据库命名

统一 **小写 + 下划线**，表名加业务前缀，避免使用 SQL 关键字。

| 前缀 | 含义 | 示例 |
| --- | --- | --- |
| `sys_` | 系统与权限 | `sys_user`、`sys_role`、`sys_user_role` |
| `pet_` | 宠物相关 | `pet_info`、`pet_medical_record` |
| `appt_` | 预约挂号 | `appt_order`、`appt_schedule` |
| `med_` | 诊疗与处方 | `med_diagnosis`、`med_prescription` |
| `stock_` | 药品与库存 | `stock_drug`、`stock_record` |
| `bill_` | 收费结算 | `bill_order`、`bill_item` |

- 字段一律 `snake_case`；主键统一 `id`；外键 `<表名去前缀>_id`；时间字段 `create_time`、`update_time`。
- 所有表必备：`id`、`create_time`、`update_time`，逻辑删除加 `deleted`。

### 3.4 前端规范

- 组件文件 `PascalCase.vue`（如 `PetForm.vue`）；页面放在 `src/views/<模块>/`。
- 目录、路由路径用 kebab-case（如 `pet-record`）。
- 与后端约定：接口路径 `/api/<模块>/<资源>`，模块名与数据库前缀语义一致。

## 四、二进制与大文件

- 论文、开题报告、PPT、图表等二进制文件**正常入库**（本课题体量小，无需 Git LFS）。
- 单个文件超过 **50 MB** 时先确认是否必要；确需入库则改用 Git LFS，并在规范中登记。
- 图片统一放各阶段目录下的 `图表源文件/`（如 `docs/02-需求分析/图表源文件/`）
  或 `frontend/src/assets/`，不散落在根目录。

## 五、禁止入库的内容

由 `.gitignore` 强制拦截：`target/`、`node_modules/`、`dist/`、IDE 配置、
本地配置文件（`application-local.yml`）、含密码/密钥的文件、日志与临时文件。
**数据库连接密码、JWT 密钥等一律不写进被跟踪的文件。**

## 六、变更本策略

如需调整目录结构或命名规范，先在 `docs/00-项目规范/` 更新本文档，
再执行实际改动，并在提交信息中注明 `docs(规范)`。
